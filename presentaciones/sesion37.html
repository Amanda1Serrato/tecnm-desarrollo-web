00–20 min: Fundamentos Teóricos — Pruebas de Integración End-to-End y Automatización CI/CD

Las pruebas E2E verifican que el sistema completo (red, auth, lógica y base de datos) funcione armónicamente de inicio a fin.

01. Colecciones de Pruebas en Postman[+]

Flujos secuenciales de peticiones HTTP: 1. Registro -> 2. Login -> 3. Guardar Token -> 4. Crear Recurso -> 5. Consultar Recurso.

Simula el comportamiento real de un usuario interactuando con la API.
02. Aserciones JavaScript en Postman Tests[+]

Scripts de validación: `pm.response.to.have.status(200)`, `pm.expect(pm.response.json().status).to.eql('success')`.

Valida automáticamente tanto los códigos de estado como el contenido de los payloads.
03. Ejecución Automatizada con Newman CLI[+]

Herramienta de línea de comandos para ejecutar colecciones de Postman dentro de pipelines de GitHub Actions o scripts locales.

Bloquea el paso a producción si alguna prueba de la suite falla.

`pm.environment.set('token', pm.response.json().access_token);`.

Inyecta el token obtenido en el login directamente en las peticiones subsecuentes de la colección.
Reportes de Cobertura y Fallos[+]

Newman emite reportes en formato CLI, HTML o JUnit XML.

Facilita la auditoría visual y la trazabilidad de regresiones en el código.

Antipatrones en Pruebas E2E

Puntos críticos de falla que deben prevenirse en producción y auditarse en las respuestas del LLM:

  • Pruebas interdependientes que fallan si no se ejecutan en un orden estricto específico.
  • No limpiar los datos de prueba creados en la base de datos tras la ejecución de la suite.
  • Escribir aserciones que solo verifican el código HTTP (200) sin validar la estructura del JSON devuelto.
