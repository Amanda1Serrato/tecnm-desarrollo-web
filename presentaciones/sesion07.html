Especificación OpenAPI (Swagger) y ReDoc

Sesión 07 del curso. Exploración conceptual, arquitectura del protocolo HTTP y diseño de servicios web con la Tríada Metodológica.

01. El Artesano[+]

Codificación manual sin IA para comprender el procesamiento de bajo nivel de la petición HTTP.

Desarrolla la intuición técnica de parseo de payloads, verbos y encabezados web.
02. El Científico[+]

Formalización de contratos de API mediante especificación C-R-E-O y esquemas DTO/OpenAPI.

Define tipos, validaciones de rango y códigos de respuesta semánticos antes de pedir código al LLM.
03. El Auditor[+]

Test Harness automatizado en Colab para auditar códigos de estado HTTP y robustez del servidor.

Somete el endpoint a pruebas destructivas (400, 404, 422) y registra la bitácora en GitHub.

00–20 min: Fundamentos Teóricos — Documentación Viva e Interoperabilidad de APIs

OpenAPI es el estándar industrial neutro para describir APIs RESTful de forma legible tanto por humanos como por máquinas.

01. Especificación OpenAPI v3.1[+]

Documento JSON/YAML que describe rutas, verbos, parámetros, esquemas de payload y códigos de respuesta.

Sustituye la documentación manual desactualizada por un contrato auditable.
02. Swagger UI (Cliente Interactivo)[+]

Interfaz gráfica que permite probar endpoints directamente desde el navegador enviando peticiones HTTP reales.

Acelera el desarrollo del frontend al proporcionar un entorno de pruebas inmediato.
03. ReDoc (Documentación Estática Enriquecida)[+]

Renderizado alternativo enfocado en la lectura limpia de esquemas de datos y contratos técnicos.

Ideal para publicar portales de desarrolladores y especificaciones oficiales.
Invariante Web: Los encabezados y códigos de estado HTTP son el lenguaje universal de comunicación entre servicios desacoplados.

Arquitectura del Servidor y Protocolo: Generación Automática del Esquema JSON

Reflexión e inspección de código en el servidor:

Endpoint `/openapi.json`[+]

El servidor inspecciona las rutas registradas y sus tipos Pydantic para construir el JSON OpenAPI dinámicamente.

Permite a herramientas externas (Postman, SDK Generators) consumir el esquema al instante.
Generación de SDKs de Cliente[+]

A partir del documento OpenAPI, es posible autogenerar clientes en TypeScript, Swift o Kotlin sin escribir código de red manual.

Garantiza sincronización total entre backend y aplicaciones móviles/web.

Puntos de Falla en Documentación OpenAPI

Puntos críticos de falla que deben protegerse en la API y auditarse en las respuestas del LLM:

  • Exponer endpoints privados o de diagnóstico interno en el esquema OpenAPI público.
  • Omitir la documentación de respuestas de error (400, 401, 403, 404, 422) mostrando únicamente la respuesta 200 OK.
  • Mantener descripciones genéricas en los esquemas sin ejemplos reales de uso.
