00–20 min: Fundamentos Teóricos — Data Transfer Objects (DTO) y Validación Estricta

Un DTO define el esquema rígido de los datos que ingresan o salen de la API, garantizando tipado seguro en tiempo de ejecución.

01. Validación en Tiempo de Ejecución[+]

Python y PHP son dinámicos; Pydantic/DTOs fuerzan la conversión y validación de tipos al recibir el JSON.

Si la entrada no coincide exactamente con el esquema, la petición es derivada automáticamente a un manejador de errores.
02. Coerción de Tipos Controlada[+]

Pydantic v2 convierte cadenas numéricas `"123"` a enteros `123` si el esquema lo define como `int`.

Evita fallos silenciosos en la capa de lógica de negocio.
03. Deserialización y Serialización[+]

Transformación bidireccional: `JSON -> DTO (Entrada)` y `Objeto/Model -> DTO -> JSON (Salida)`.

Aísla el modelo interno de la base de datos de la representación pública enviada al cliente.
Invariante Web: Los encabezados y códigos de estado HTTP son el lenguaje universal de comunicación entre servicios desacoplados.

Arquitectura del Servidor y Protocolo: Arquitectura de Pydantic v2 (Rust Core)

Rendimiento y seguridad de esquemas de datos:

Motor Pydantic-Core (Rust)[+]

Pydantic v2 ejecuta la validación de esquemas compilada en Rust, alcanzando velocidades de 5x a 50x superiores a v1.

Garantiza consumo de memoria mínimo bajo tráfico masivo.
Código HTTP 422 Unprocessable Entity[+]

Respuesta estándar cuando el JSON es sintácticamente válido pero viola los tipos o restricciones del DTO.

Devuelve una lista detallada con los campos exactos que fallaron.

Puntos de Falla en DTOs

Puntos críticos de falla que deben protegerse en la API y auditarse en las respuestas del LLM:

  • Exponer entidades de base de datos directamente en el endpoint en lugar de usar DTOs de salida.
  • Permitir la inyección de campos no declarados en el esquema (*Mass Assignment Vulnerability*).
  • Omitir valores por defecto en campos opcionales causando errores de atributo nulo (`NoneType`).
