Hito 4: Demostración API Full-Stack en Producción con SPA

Sesión 40 del curso. Despliegue en producción, arquitectura SPA en cliente, pruebas E2E y observabilidad con la Tríada Metodológica.

01. El Artesano[+]

Codificación manual sin IA para experimentar el consumo con Fetch, manejo de DOM y Dockerfiles.

Desarrolla la intuición técnica de peticiones de red asíncronas, estado cliente y contenedores.
02. El Científico[+]

Especificación C-R-E-O para arquitecturas de despliegue PaaS, SPA sin recarga y suites E2E.

Define contratos de integración frontend-backend, tareas en background y healthchecks estandarizados.
03. El Auditor[+]

Test Harness automatizado con Newman CLI, verificación de latencia y pruebas de estado en vivo.

Somete la plataforma web completa a pruebas de estrés y registra el release final en GitHub.

00–20 min: Fundamentos Teóricos — Evaluación Integradora y Demostración de la Plataforma Web

Culminación del curso. Demostración práctica de una plataforma web Full-Stack completa, segura y desplegada en la nube con SPA reactiva.

01. Sistema Full-Stack Integrado[+]

Backend RESTful asíncrono con base de datos relacional, auth JWT, RBAC, validación estricta y frontend SPA dinámico.

Demuestra el dominio de la arquitectura web de extremo a extremo.
02. Despliegue Público en Producción[+]

API y cliente web accesibles públicamente con HTTPS en la nube (Render / Codespaces / GitHub Pages).

Evidencia formal de software desplegado con estándares profesionales de la industria.
03. Entrega Final y Release en GitHub[+]

Etiquetado formal de la versión definitiva en el repositorio: `git tag v1.0-final`.

Concluye el 30% del Proyecto Integrador y la acreditación final del curso.
Invariante de Producción: Una aplicación web profesional debe ser observable, escalable y reproducible en cualquier infraestructura.

Arquitectura de Despliegue y Frontend: Auditoría Final y Criterios de Acreditación

Verificación del ecosistema en vivo:

Suite E2E Automatizada Exitosa[+]

Ejecución al 100% de la colección de pruebas en Newman/Postman validando todos los flujos de usuario.

Certifica la solidez técnica y ausencia de regresiones en la plataforma.
Documentación de Arquitectura Completa[+]

Especificación OpenAPI viva, esquemas de base de datos, diagrama de capas y bitácoras de auditoría en GitHub.

Constituye el portafolio profesional de evidencias del estudiante.

Criterios de Acreditación del Hito 4

Puntos críticos de falla que deben prevenirse en producción y auditarse en las respuestas del LLM:

  • La aplicación debe estar desplegada en la nube y accesible mediante HTTPS sin errores de servidor.
  • El frontend SPA debe consumir la API REST de forma reactiva con manejo de tokens JWT y roles.
  • El repositorio en GitHub debe contener las 40 bitácoras de auditoría completas y el tag `v1.0-final`.

Dinámica del Laboratorio y Protocolo de Entrega

  • 20–35 min: Fase 1: El Artesano (Código manual sin IA).

Verifica que las pruebas E2E terminen con 0 fallos antes de hacer el commit final.
