00–20 min: Fundamentos Teóricos — Metodología 12-Factor App y Despliegue Continuo (CD)

El despliegue moderno desacopla la configuración del código fuente mediante variables de entorno inyectadas en tiempo de ejecución.

01. The Twelve-Factor App (Configuración)[+]

Toda configuración que cambie entre entornos (Dev, Staging, Prod) debe residir en variables de entorno del sistema operativo.

El código base es estrictamente el mismo en todos los despliegues.
02. Plataformas PaaS (Render / Codespaces)[+]

Plataformas que automatizan la construcción, aprovisionamiento de certificados SSL/TLS y despliegue directo desde Git.

Cada `git push origin main` dispara una compilación y despliegue sin tiempo de inactividad (*Zero-Downtime*).
03. Gestión de Secretos y Variables Sensibles[+]

Las claves secretas (`SECRET_KEY`, `DATABASE_URL`) se configuran en el panel de la nube, nunca en el repositorio.

Protege las credenciales corporativas ante repositorios públicos o filtraciones de código.

Validación de Configuración al Arrancar[+]

La aplicación valida que todas las variables requeridas existan antes de abrir puertos de red.

Falla rápido (*Fail-Fast*) si falta una variable crítica de base de datos.
Terminación SSL/TLS Automática[+]

El PaaS gestiona los certificados HTTPS mediante Let's Encrypt de forma automática en el borde de la red.

Cifra todo el tráfico entre el navegador del cliente y el balanceador del PaaS.

Puntos de Falla en Despliegues Cloud

Puntos críticos de falla que deben prevenirse en producción y auditarse en las respuestas del LLM:

  • Hacer commit del archivo `.env` local en GitHub exponiendo contraseñas de producción.
  • Codificar rutas locales fijas (`C:\Users\...` o `/home/ivan/...`) que no existen en el contenedor Linux de producción.
  • No configurar el puerto dinámico asignado por el PaaS mediante la variable `$PORT`.
